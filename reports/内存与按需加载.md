# 桌面端内存与按需加载

桌面画廊采用 `ui.List` 做控件虚拟化。等比布局仍需要所有匹配条目的 ID、名称、尺寸等轻量信息，以计算完整滚动范围；原图、完整元数据和解码后的图片不随这个索引全量加载。

## 加载与回收

- 打开素材库不再预热全库 `Item` / 搜索字符串缓存，也不再自动解码后台图片来补全元数据。
- 画廊通过 SQLite 读取轻量索引；卡片按可见区域加载，每页 96 条，最多保留 4 页。卡片不读取 Prompt、备注和扩展元数据。
- 检查器、预览及需要完整信息的操作按 ID 获取详情。页面淘汰保留布局信息和选择 ID，释放卡片路径及其他详情。
- 布局只在数据、窗口宽度、缩放、布局模式或文件夹状态变化时重建。滚动帧复用现有布局。
- 画廊缩略图缓存最多保留 96 项，同时按估算像素占用执行 64 MiB 预算。这不是整个应用或 GPU 内存的硬上限。
- 当前原图预览使用独立的单项缓存及一个解码任务，不排在画廊缩略图队列之后，也不被预览底部缩略图挤出缓存。单张超预算原图允许独占预览缓存；关闭或切换预览时清除。
- 底部胶片条使用独立缩略图缓存，最多 96 项、估算像素预算 12 MiB、两个解码任务。全屏预览下方仍在绘制的画廊不会挤出胶片条的位图；关闭预览时清除，切换相邻条目时复用。可见数量不超过缓存容量。
- 图片请求按路径和目标尺寸区分，画廊最多两个并发解码任务。清理、失效或淘汰后的任务不能重新写回缓存。解码成功或失败都会通知主窗口重建内容。
- 缩略图及配色补全由可见卡片触发，自动等待队列最多 64 项、两个并发；优先利用已有缩略图提取配色。
- 关闭预览、切换页面或隐藏窗口会清理对应预览资源；隐藏窗口也会停止继续调度旧缩略图队列。
- 多选检查器只构建最后五个条目的预览栈，不复制完整选区的所有 `Item` 来绘制堆叠。
- 虚拟文件夹来自 SQLite 的 `folders.parent_id` 与 `item_folders` 引用关系，不扫描物理目录。刷新时在后台构建文件夹索引，侧栏、文件夹卡片、标题、菜单和筛选器共享 ID、父子关系、根节点及路径标签缓存；重绘不查询 SQLite，也不重新展开整棵树。

文件夹索引随 SQLite 查询结果一起替换，保留查询返回的排序和条目计数。创建、重命名、移动、排序、删除文件夹，以及切换或关闭素材库后，旧快照会被替换。展开、折叠及普通滚动复用现有索引。

“显示直属子文件夹内容”只包含当前文件夹与直属子文件夹的素材，不继续收集孙级、曾孙级或其他分支。例如 `A / B / C` 中，在 A 开启此选项会查询 A 与 B，进入 B 后才会查询 B 与 C。子文件夹卡片的封面及计数只读取该子文件夹自身的关联素材，不额外向下展开。

素材库已加载时，切换该选项只刷新当前作用域的素材及直属子文件夹预览，复用现有文件夹快照，不重新读取全库的文件夹、标签及统计。库仍在加载或切换时保留完整刷新，避免丢失库信息。

SQLite 文件夹范围查询从 `item_folders.folder_id` 索引定位关联条目，再通过条目 ID 查询素材；多重归属的素材只返回一次。查询计划回归测试检查关联索引被使用，并避免逐条扫描全库素材检查文件夹关系。

复杂搜索仍会流式扫描匹配字段，以保持原有 Unicode 文本、颜色距离和组合筛选语义；这些完整元数据不会常驻内存。轻量索引和布局本身仍随结果条目数增长。

## 预览加载诊断

预览事件写入现有 `app.log` 和应用内诊断日志，分类为 `preview`。每条记录带有 `request` 请求编号、素材 ID、列表索引、模式、实际文件路径和 `elapsed_us` 耗时。先搜索 `preview`，再按请求编号关联同一次加载；不记录备注、Prompt 或图片内容。

| 阶段 | 含义 |
| --- | --- |
| `requested` / `metadata_ready` | 用户打开或切换预览，完成条目元数据查询 |
| `decode_started` | 解码任务开始，耗时字段表示排队和调度等待 |
| `read_header` / `read_file` | 读取格式、原始尺寸和文件字节，文件读取单独计时 |
| `decode_source` / `resize` | 大图的源解码和缩放，分别计时 |
| `encode_resized` / `decode_bitmap` | 必要时重编码缩放结果，再构建显示位图 |
| `cached` / `display_ready` | 位图进入缓存，以及 UI 首次取得位图准备绘制；后者不是 GPU 完成显示的时间 |
| `waiting` | 超过两秒仍未取得位图，记录一次当前活动任务和队列长度 |
| `metadata_failed` / `failed` / `display_failed` | 元数据或解码错误，保留错误原因并显示重试操作 |
| `superseded` / `discarded` / `closed` | 切换、过期任务被丢弃及关闭预览 |
| `filmstrip_requested` / `filmstrip_ready` / `filmstrip_waiting` | 底部胶片条的可见索引范围、成功数、等待数、失败数及缺失路径数；同一窗口范围只记录一次完成或超时等待 |

错误结果不会被当作仍在加载的占位项，也不会逐帧重试和刷日志。重试会产生新的请求编号并清除旧错误。当前预览的回归测试覆盖中间分页位置、缩略图缓存压力、超预算单张原图、失败后的点击重试及 JPEG EXIF 方向。

胶片条单项完成事件以 `Filmstrip preview cached/failed/discarded` 记录条目 ID、索引及缩略图路径，不对每张小图重复输出原图的全部解码阶段。像素回归测试在三万条目中间位置逐帧制造超过画廊缓存容量的请求，并验证底部实际绘制缩略图。

## 验证记录

2026-11-14，Apple M1，三万条目合成库，基准每项运行三次：

| 路径 | 单次耗时 | 单次累计分配 |
| --- | ---: | ---: |
| 读取轻量索引 | 约 62.6 ms | 约 25.5 MiB |
| 读取 96 条卡片 | 约 0.60 ms | 约 253 KiB |
| 重建完整布局 | 约 1.10 ms | 约 3.27 MiB |
| 复用未变化的布局 | 约 403 ns | 0 B / 0 次分配 |

分配量是一次操作累计申请的空间，不等于操作完成后的存活堆或进程物理足迹。

真实 37,493 条目库的排查快照中，较早进程的物理足迹为 406.1 MiB、峰值 558.5 MiB；后续移除临时采样及强制 GC 后，自然运行进程的快照为 157.9 MiB、峰值 212.1 MiB。两次来自不同开发进程，不是相同操作序列的长期压力测试。

后续检查中，进程 84485 的物理足迹再次达到 408.6 MiB，历史峰值为 737.0 MiB。现场确认图片缓存仍为 96 项、卡片缓存仍为 4 页、完整库缓存未加载；进一步发现侧栏对子文件夹的查询会逐节点展开并复制全树。因此，上述启动快照不能作为持续操作后的稳定内存结论。

以 511 个虚拟文件夹、35 个根节点做对照，每项运行五次：

| 子文件夹查询场景 | 修复前耗时 | 缓存后耗时 | 修复前累计分配 | 缓存后累计分配 |
| --- | ---: | ---: | ---: | ---: |
| 35 个折叠根节点 | 约 1.12 ms | 约 0.47 μs | 约 5.26 MiB | 0 B / 0 次 |
| 511 个可见文件夹 | 约 12.31 ms | 约 13.13 μs | 约 76.79 MiB | 0 B / 0 次 |

此处只衡量文件夹关系查询，不代表整个 UI 绘制零分配，也不证明上述峰值完全来自这一处。回归测试同时验证 SQLite 中的重命名、移动、排序及删除结果能更新缓存。

三万条目合成库中，一个关联 14 条有效素材的文件夹，统计查询由逐条检查全库的约 18.11 ms 降至关联索引查询的约 0.053 ms（每项五次）。这是单个文件夹统计查询的对照，不代表整个视图切换的耗时。

