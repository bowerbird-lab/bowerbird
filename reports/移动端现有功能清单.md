## 1. 产品边界与页面结构

现有移动端是桌面素材库的网络伴侣：桌面端负责资源库、原文件、索引、查询和导入，手机通过 HTTP 与 WebSocket 浏览及操作当前资源库。手机另外保留待上传的分享收件箱、连接记录、使用历史和手机分享标记。

当前仓库只有 Android 原生工程，未发现 `mobile/ios/`。不能把 Flutter 的跨平台能力等同于已经交付 iOS 客户端。

| 页面/区域 | 已有能力 | 主要代码 |
|---|---|---|
| 应用入口 | 初始化连接、收件箱和分享标记；根据配置进入连接页或首页；系统深浅色；深链与前后台分享事件 | `mobile/lib/main.dart` |
| 连接页 | 服务发现、手动 IP/端口、历史连接、配对码、扫码入口 | `mobile/lib/screens/connect_screen.dart` |
| 扫码页 | 二维码识别、候选 IP 探测、配对、闪光灯、切换摄像头、权限错误与重试 | `mobile/lib/screens/scan_screen.dart` |
| 素材首页 | 月份分组、分页网格、筛选、侧栏、网格密度手势、多选、上传、菜单 | `mobile/lib/screens/home_screen.dart`、`controllers/`、`screens/home/widgets/` |
| 搜索页 | 文本与多维筛选、结果总数、分页、详情跳转、远端更新刷新 | `mobile/lib/screens/search_screen.dart`、`screens/search/widgets/` |
| 素材详情 | 图片/GIF/视频、左右翻页、信息弹层、复制、下载、分享、删除 | `mobile/lib/screens/detail_screen.dart`、`screens/detail/widgets/` |
| 快速预览 | 媒体预览、底部操作抽屉、拖动关闭、查看详情/复制/下载/分享/删除 | `mobile/lib/widgets/item_preview_overlay.dart` |
| 收件箱 | 离线暂存、文件/文本列表、单项与全部上传、失败重试、删除 | `mobile/lib/screens/inbox_screen.dart`、`services/inbox_*` |

| Q05 | 兼容旧桌面端 | `/query` 返回 404/405 后回退 `/items`，重连/配对后重新探测 | `services/api_items.dart` |

边界：

- 首页与搜索页面的布局、角标、动画策略并不完全一致，应按用户能力对齐，避免复制两套查询与媒体逻辑。
- 首页对 `≤ 8 × 1024 × 1024` 字节的 GIF 请求原图播放，大 GIF 使用静态缩略图。
- 旧 `/items` 接口只能承载文本、标签、目录、颜色、类型和方向；大小、评分、URL/备注有无、未分类/未打标签的完整语义无法直接传递。现有回退会丢掉部分条件，新版需要提示不支持，不能把宽泛结果显示为完整筛选结果。
- 旧桌面端缺少 `/stats` 时，当前通过三次查询估算总数、未分类、未打标签，废纸篓计数返回 0；这属于兼容降级。
- API 支持排序参数，但当前页面没有完整的用户排序选择器，不计为已交付的排序功能。

- 视频范围请求由桌面原文件接口提供；具体格式能否播放取决于解码器，不能把“有视频文件”视为“所有视频格式均可播放”。

- 当前下载实现按图片/视频选择 `MediaStore` 集合；提示文案中的“下载目录”不代表任意文件都已正确导出到 Downloads。
- 快速分享在调起分享面板前记录历史；不能将其描述为已经确认目标应用发送成功。

## 3. API 与事件契约

以 `core/mobile_api.go` 的注册路由与方法分派为准；`mobile/API.md` 是补充说明。新客户端应有独立 DTO 和逐端点解码，当前响应并非统一包装格式。

| 方法 | 路径 | 用途/约束 |
|---|---|---|
| GET | `/api/v1/status` | 公开状态、库名、版本、是否需要配对 |
| POST | `/api/v1/pair` | 公开配对换 token |
| GET | `/api/v1/ws`（兼容 `/ws`） | WebSocket 事件；允许 query token |
| GET | `/api/v1/libraries` | 库列表及活动状态 |
| POST | `/api/v1/libraries/switch` | `id/path`；修改桌面活动库 |
| POST | `/api/v1/query` | `query/sort/offset/limit`；上限 500 条；`{total,limit,offset,items}` |
| GET | `/api/v1/items` | 旧查询参数；上限 200 条 |
| GET | `/api/v1/stats` | 集合统计、容量和主色信息 |
| GET | `/api/v1/items/collection?name=...` | `trash/untagged/uncategorized`；分页上限 500 条 |
| DELETE | `/api/v1/items/collection?name=trash` | 清空废纸篓 |
| GET | `/api/v1/items/{id}` | 完整元数据 |
| DELETE | `/api/v1/items/{id}` | 移入废纸篓 |
| POST | `/api/v1/items/{id}/restore` | 恢复素材 |
| POST | `/api/v1/items/{id}/tags` | 请求体 `{tag}`；添加标签 |
| POST | `/api/v1/items/{id}/folders` | 请求体 `{folderId}`；加入文件夹 |
| GET | `/api/v1/tags`、`/folders`、`/colors` | 分类元数据 |
| GET/HEAD | `/api/v1/thumbs/{id}` | 缩略图；缺失时回退原图 |
| GET/HEAD | `/api/v1/originals/{id}` | 原文件；支持 Range/HEAD，视频 seek 依赖此接口 |
| POST | `/api/v1/upload` | multipart `file`；请求体总上限 `500 << 20` 字节，包含 multipart 开销 |

除 status/pair 外按既有鉴权处理。普通 HTTP 使用 Bearer，媒体 URL 和 WebSocket 现有实现也携带 query token。新版日志、缓存键和错误提示应去掉敏感查询参数。

需要覆盖的事件语义：素材变更重新取当前窗口；活动库变更使旧库数据失效；授权撤销清除当前会话并返回连接流程；断线重连后主动补刷新，不能依赖离线期间事件重放。

## 4. 本地数据与平台依赖

| 数据 | 当前位置/格式 | 重写迁移要求 |
|---|---|---|
| 当前连接 | secure storage：`bowerbird_base_url`、`bowerbird_token`、`bowerbird_library_name` | 原生读取旧加密存储并迁移；解密失败允许重新配对 |
| 历史连接 | secure storage：`bowerbird_history_connections` | 保留最多 10 条及候选 IP/token；不可明文写入普通 JSON |
| 使用历史 | secure storage：`bowerbird_usage_history` | 保留顺序和最多 500 个 ID；当前没有按库隔离 |
| 收件箱索引 | support 目录下 `share_inbox/index.json`，version 1，含 `entries/processedEvents`；失败时可能位于 cache | 路径须用旧版实机定位；迁移相对 `storedPath` 与文件，不能只迁索引 |
| 原生待接收队列 | `filesDir/share_inbox/pending/*.json` 与事件素材目录 | 升级时先接管 pending，再确认持久化；防止重复/丢失 |
| 原生分享去重 | SharedPreferences `bowerbird_share` | 兼容窗口或安全重建，不得把新分享永久判重 |
| 手机分享标记 | documents 目录下 `share_inbox/share_tags.json`，version 1 | 与 InboxStore 的 support 根目录不同，必须分别查找 |
| 剪贴板/上传/分享缓存 | cache 下 `clipboard/`、`share_inbox_upload/` 等 | 可重建；正在被外部应用读取的文件不立即清理 |

当前原生桥分两条 MethodChannel：`com.bowerbird.mobile/native_bridge` 提供选文件、保存媒体、复制文件；`com.bowerbird.mobile/share` 提供 pending 分享消费与可用事件通知。替换 Flutter 后保留这些能力，通信实现需要重写。

Android 标识要区分：`namespace` 与 Kotlin 包为 `com.bowerbird.bowerbird_mobile`，实际 `applicationId` 为 **`com.bowerbird.mobile`**；FileProvider authority 为 `${applicationId}.fileprovider`。

## 5. 已知缺口与范围约束

下列内容不是“已经完成的现有功能”，应在重写方案中单列决策：

1. iOS 工程、音频播放器、专用文档阅读器、离线完整素材库和后台持续上传尚未实现。
2. 标签/目录已有添加与批量添加，但未发现完整的移动端重命名、移除、目录管理界面；评分能筛选，不等于能编辑。
3. 详情与快速操作的分享历史记录不一致；首页删除回传与 WebSocket 刷新耦合，需统一动作结果。
4. 部分下载/分享将整个原文件读入内存；重写应统一流式文件处理，避免大视频造成内存峰值。
5. 原生消费 pending 时即删除事件文件，Dart 持久化与消费之间存在中断窗口；新版需要接收确认协议。
6. 旧查询回退会丢失筛选语义，统计降级可能把不支持误显示为 0；新版应明确能力边界。
7. 分享标记以库名隔离、使用历史仅存 ID，存在同名库/跨库混淆；改用稳定库 ID 前要设计旧数据映射。
8. Android release 配置当前使用 debug signing，CI 未显示独立正式 keystore 注入；覆盖升级能力必须按实际已发 APK 证书核对。
9. 旧的 [移动端 v3.1 方案](移动端v3.1方案.md) 描述过“无废纸篓恢复”等历史状态，与当前代码不同。后续重写以本清单和代码为准。

首版 NSGo 替换的完成条件是上述已有能力全部可追踪验收；能力新增项另行排期。功能删减必须在迁移矩阵明确说明并确认，不能仅因 Flutter 插件无法直接复用而省略。
