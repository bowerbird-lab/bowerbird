# Bowerbird 移动端 NSGo 重写方案

> 日期：2026-11-15。现有代码基线：`bc3ae77`。
> 状态：待实施计划。本轮仅整理功能与编写文档，不引入依赖、不创建新客户端、不删除 Flutter。
> 功能基线：[移动端现有功能清单](移动端现有功能清单.md)。

## 1. 目标与实施边界

使用 NSGo 重写整个移动客户端，以 Go 实现页面、状态和客户端业务，最终移除移动端 Flutter/Dart、Flutter 插件及构建依赖。首个替换平台为已有工程覆盖的 Android；架构预留 iOS，iOS 作为后续独立交付，不列入 Android 替换的前置范围。

新客户端继续连接现有桌面 HTTP/WebSocket API，沿用配对协议和桌面活动资源库模型。桌面端继续管理文件和数据库；不把桌面 `core` 包及其桌面 UI、插件运行时、SQLite 等整套依赖直接带进手机。

实施期间旧客户端作为功能、真机表现和数据迁移的对照。达到替换验收后，移动端唯一主实现切换为 NSGo，并删除 Flutter 工程；开发阶段的源码并存不意味着长期维护两套客户端。

## 2. NSGo 调研结论

调研以 2026-11-15 查询到的官方文档和官方源码为准。以下是技术选型依据，不是 Bowerbird 已验证的结果。

| 项目 | 官方资料中的状态 | 本项目决策 |
|---|---|---|
| 成熟度 | 官方明确标注 early，暂无稳定 API/正式 release | 固定依赖 commit/pseudo-version，先做真机技术验证；禁止 CI 跟随 main/latest |
| 编程与渲染 | Go 组件、signals；Android 使用原生 Views，iOS 使用 UIKit/CoreText | 页面与状态优先纯 Go，不引入 TSX 作为另一套业务层 |
| Android 运行方式 | Android Java runtime 与 Go 可执行进程通过 pipes 通信；arm64 真机、x86_64 模拟器有运行路径 | 不假设与 Kotlin 同进程；宿主桥传路径与小对象，不传整个视频字节 |
| 嵌入 | 官方支持 `-embed` 输出 Android AAR，`NsgoView`、Host channel、自定义原生组件 | 推荐自有 Kotlin Android 宿主 + NSGo AAR，便于接管现有原生能力 |
| 工具链 | 官方当前 `go.mod` 要求 Go 1.27.3；仓库根模块也是 1.27.3 | 新移动端独立 Go module；在 P0 锁定 Go、NSGo、JDK、SDK/NDK 和 Gradle 版本 |
| 长列表 | 官方文档有虚拟列表、多列、加载更多、可见区域与滚动定位能力 | 用于素材网格；月份分组、动态改列和锚点恢复在真机验证 |
| 平台服务 | 官方提供 HTTP 接入、文件选择、分享、文字/图片剪贴板、文件存储与生命周期接口 | 有接口不等于满足全部现有语义；文件 URI 剪贴板、分享接收、凭据加密逐项验证 |
| 发布工具 | 官方文档描述 APK/AAB、签名配置和嵌入产物 | 自有宿主路线最终 APK/AAB 由 Gradle 构建签名，NSGo 负责嵌入 AAR |

资料之间可能存在更新差异：例如公共列表文档出现的能力仍可能在 roadmap 列出补齐项；Android 明文 HTTP 配置也在 roadmap 中出现。因此开发时以**锁定 commit 的源码与实际产物**为准，不按官网演示或 benchmark 直接承诺兼容性、包体和性能。

## 3. 目标架构与目录

推荐采用自有 Kotlin 宿主承载 NSGo 页面。这样可以保留系统分享入口、Provider、MediaStore 等平台控制点，并通过官方 Host channel 接入 Go；最终安装包不包含 Flutter runtime。该路线须先通过 P0 的嵌入与发布验证。

```text
Android Kotlin 宿主
  Activity / Intent / 权限 / Keystore / 分享接收 / 文件与媒体
               ↕ NSGo Host channel / 原生组件
NSGo Go 客户端
  页面与主题 → 页面状态 → 用例与仓储 → HTTP / WebSocket
                              ↘ 本地收件箱、标记、使用历史
               ↕ 现有 /api/v1/*
Bowerbird 桌面端
  MobileServer → 查询、资源库、文件、导入、废纸篓
```

建议目录（下列路径是待创建的设计）：

```text
mobile/                         # 过渡期现有 Flutter；P7 删除
mobile-nsgo/
  go.mod / go.sum               # 不依赖根模块的桌面 core
  nsgo.yaml                    # 嵌入目标、标识、版本
  main.go
  internal/
    app/                       # 启动、路由、会话与前后台生命周期
    model/                     # DTO 与客户端领域模型
    transport/                 # HTTP、错误解码、WS、能力探测
    repository/                # 素材、分类、库、收件箱与本地历史
    usecase/                   # 配对、导入、分享、删除、恢复、批量操作
    state/                     # 各页面状态、请求取消、列表锚点
    ui/                        # connect、gallery、search、detail、inbox
    platform/                  # Host channel 的 Go 接口与实现
    storage/                   # 版本化 JSON、迁移、原子写入
  android/                     # Kotlin 宿主、Gradle、Manifest、原生组件
  assets/
  testdata/                    # 脱敏 API/事件/迁移样本
  README.md
```

P7 后可将 `mobile-nsgo/` 统一更名为 `mobile/`，同步 CI、文档和脚本。功能迁移与最终目录移动分开提交，方便审查。

### 3.1 模块规则

1. **transport**：注入 base URL/token/HTTP client；逐端点解码；设置超时、取消、错误分类；不持有 UI。可评估沿用仓库使用的 `github.com/coder/websocket`，但在新模块独立锁定版本。
2. **repository/usecase**：集中素材操作与本地数据；详情和快捷预览调用同一分享、下载、删除流程；批量操作返回逐项结果。
3. **state**：所有异步请求绑定 `server/session/library/query` 代次。会话、库、筛选变化时取消旧请求；迟到结果不得进入新页面。
4. **ui**：通过 NSGo signals 展示状态，异步结果经框架调度回到状态所属线程；页面不直接拼接请求和文件操作。
5. **platform**：定义扫码、发现、凭据、文件选择、相册导出、剪贴板、系统分享、分享队列和生命周期契约；把 Android 实现限制在宿主。
6. **storage**：索引与普通偏好存文件；token 通过宿主加密存储。NSGo 普通 key-value storage 不能在未核实加密能力时替代旧 secure storage。

### 3.2 原生能力替换表

| 旧依赖/能力 | NSGo 重写安排 | 首轮验证重点 |
|---|---|---|
| Flutter 页面、主题、导航 | NSGo Go 组件/signals/路由与设计 token | 返回键、安全区、输入法、暗色、大字号 |
| `http` / JSON / crypto | `net/http`、`encoding/json`、`crypto/sha256` | 鉴权、响应包装差异、流式上传/下载 |
| `multicast_dns` | 优先 Android NSD 宿主适配，必要时评估纯 Go mDNS | Wi-Fi/VPN、重复服务、超时、扫描停止 |
| `flutter_secure_storage` | 宿主安全存储 + 旧格式兼容迁移器 | 实际旧插件存储格式、Keystore 兼容、重装/覆盖差异 |
| `mobile_scanner` | Android 原生扫码组件，经宿主返回 payload | 摄像头权限、拒绝重试、闪光灯、切镜头、重复识别 |
| `app_links` | Activity `onCreate/onNewIntent` + Host event | 冷启动延迟投递、运行中去重、异常链接 |
| `photo_view` | NSGo 滚动/缩放能力；不足时注册宿主媒体组件 | 原图缩放、横向翻页冲突、GIF 动画、内存 |
| `video_player` | 先验证 NSGo 锁定版本的媒体能力；不满足时用宿主 Media3 组件 | Bearer/Range、seek、暂停、销毁、音频焦点 |
| `share_plus` | 验证 NSGo 分享服务；需要时使用宿主 FileProvider + Intent | URI 读取权限、取消、缓存存活 |
| `path_provider` | 宿主提供明确的 data/cache 路径 | 旧 support/documents 路径分别迁移、跨进程可读 |
| 文件剪贴板 | 迁移现有 `ClipData`/FileProvider 逻辑 | 保留 MIME、URI 授权、500 MB 上限与缓存期限 |
| 文件选择/相册保存 | Kotlin 封装现有逻辑，改为路径/流接口 | 多选、进度、取消、大文件、非图片导出 |
| 系统分享接收 | Kotlin 接收与暂存，Go inbox 消费并确认 | 冷热启动、多文件/文本、杀进程、逐项错误 |

NSGo Android 的进程模型要求明确资源所有权：宿主管理相机、播放器、ContentResolver 与 URI 权限；Go 管理请求和业务队列；所有组件停止时释放资源。Host 消息携带 request ID、成功/取消/错误及事件 ID，支持延迟回调；不通过 JSON/base64 往返大文件。

## 4. 协议、同步与媒体策略

### 4.1 接口兼容

覆盖功能清单中的所有端点，不为重写先行更改服务端响应格式。

- 首次连接、重连后探测 `/query`；仅 404/405 表示走旧列表，401 是会话问题，不能当成“不支持”。
- 基础筛选可回退 `/items`；高级筛选无法表达时禁用对应入口并解释需升级桌面端。不得拉一页后本地过滤并声称总数正确。
- stats、trash、restore、tags、folders 等按各自能力处理，不从 `/query` 可用推断其他接口都可用。探测避免用危险写操作。
- 默认每页 60；窗口超过接口上限时按页补取或缩短窗口并保留锚点，不发送超上限请求后误以为已取全。
- 上传保持 multipart `file` 契约；服务端 `500 << 20` 是请求总上限，客户端预算扣除开销；与剪贴板的 `500,000,000` 字节阈值分开定义。
- `switchLibrary` 会影响桌面与其他手机，完成后重置当前列表、选择、详情、统计、标记作用域。

### 4.2 WebSocket 与生命周期

保留三种事件，重连初期沿用现有退避节奏并增加取消及去重保护。先注册监听再连接；退出会话要取消重连定时器与在途连接。

`items_updated` 合并刷新，按当前查询重新取窗口；本地删除/恢复/打标签直接更新并等待校准。当前 900 ms 忽略回声可能漏掉其他设备的变更，新版用“本地已更新 + 延迟校准”替代盲目丢弃事件。

`library_changed` 更新库身份并使所有旧库请求失效；`pairing_revoked` 立即结束当前会话和受保护请求。前台恢复/断线重连后补拉状态与当前页面，默认服务端不提供事件重放。

### 4.3 媒体与长列表

- 缩略图缓存按服务器、库、素材 ID、变体隔离；注销/切库后不复用错误作用域。日志与磁盘键不落完整带 token 的 URL。
- 首页保留小 GIF 动画阈值，限制同时播放数量，离屏停止；搜索默认静态缩略图。具体数量和缓存预算由 P0 测量后固定。
- 详情只激活当前视频，翻页/后台暂停，离页销毁；不支持格式给出原因及下载/分享入口。
- 复制、下载、分享共用流式下载任务，使用唯一临时名、`.part`、完成后 rename；支持进度、取消、失败清理；避免同名素材互相覆盖。
- 宿主从文件路径写 MediaStore；普通文件通过 SAF/Downloads 路线导出。具体 Android API 分支在 P0 验证，作为对现有泛用文件保存缺口的补齐。
- 素材列表以稳定 ID 为 key；分组后仍保持可定位的扁平索引。密度切换前后以首个可见素材 ID + 偏移恢复位置。

## 5. 用户数据迁移与覆盖升级

采用同应用覆盖升级，目标保留 `applicationId = com.bowerbird.mobile`。`namespace` 可内部调整，但不影响识别旧数据；Provider authority、分享入口与配对 scheme 保持可兼容。

覆盖升级条件必须用实际已发 APK 校验：包名、签名证书、versionCode 和 ABI。仓库当前 release 使用 debug signing，不据此推定所有已发布包证书相同；也不能直接把现有 `1.0.1+2` 的 `2` 当作已安装 ABI 分包的最终 versionCode。P0 用已发布 APK 读取真实值，再制定递增策略。

迁移步骤：

1. 由宿主定位旧 secure storage、support/documents、原生 `filesDir/share_inbox` 及 cache fallback；用包含待上传数据的旧 APK 样本确认路径。
2. 导入当前连接、历史连接与使用历史。加密格式不兼容时提供重新配对，保留文件和收件箱，不能要求用户卸载应用解决。
3. 迁移 inbox version 1 的索引、相对路径文件、processed event ID；另行迁移 documents 根下的 `share_tags.json`，不能误认为与 inbox 同目录。
4. 接管 pending JSON 与尚未移动的原生素材，持久化成功后再确认；引入 `peek → persist → ack`，进程中断可重放但不重复入箱。
5. 使用临时文件、原子替换及分步骤迁移日志；完成校验后写迁移版本。失败允许重试，迁移完成前保留旧文件，不因索引解析失败清空源数据。
6. 第一版保留旧库名标记兼容读取。能从当前服务端获取稳定库 ID 时建立映射；同名库无法唯一映射则保留为 legacy scope，不自动混并。
7. 新使用历史按服务器/稳定库身份隔离；旧仅 ID 历史作为 legacy 数据，加载时校验可用性，不推断其原库。

验收数据至少包括：未配对、已配对/多历史连接、文件和文本收件箱、pending 未消费、重复事件、来源标记、500 条历史、损坏条目、缺失文件和迁移中断。

回退要区分源码与已安装应用。源码可回到旧实现；用户应用不能依赖低 versionCode 覆盖安装。准备更高 versionCode、同证书的应急构建，并在过渡版本采用旧格式兼容读取/必要的兼容写入；若存在新数据无法被旧版读取，先验证转换方案，不能承诺直接安装旧 APK 回滚。

## 6. 分阶段实施计划

工作量是初步估算，按一位熟悉 Go/Android 的开发者计算，包含阶段验证；没有 NSGo Android 实测依据，不能视为固定交付日期。P0 后重新估算。

### 6.1 P0 必须回答的问题

| 验证项 | 最小实验 | 决策门槛 |
|---|---|---|
| 构建与宿主桥 | 从干净环境产出 AAR，再由 Kotlin 宿主构建可安装 APK；测试请求/事件/销毁 | 构建可复现，进程退出不泄漏；记录锁定版本及完整命令 |
| 网络 | 真机请求现有 `http://IP:17878`、Bearer API、带鉴权图片、WS，测试 Tailscale 候选地址 | 确认宿主和 Go/媒体各自网络路径；明文流量和 VPN 下行为可解释 |
| 网格 | 10,000 条测试库，分组多列、翻页、改列与长按 | 可见项虚拟化；滚动/内存可测；手势不破坏滚动 |
| 详情媒体 | 大图、大小 GIF、MP4/不支持视频、Range seek、快速翻页、后台恢复 | 能实现旧有能力；缺失项有已跑通的原生组件路径 |
| Android 系统能力 | 扫码、文件多选、相册保存、文件 URI 复制、向外分享、外部分享进来 | 冷热启动均可完成；拒绝权限/取消/部分失败有结果 |
| 升级与存储 | 用实际旧 APK 创建连接、收件箱和 pending，随后原地升级 | 包名/证书/版本策略明确；能读取加密数据或重新配对；待上传内容不丢 |
| CI 环境 | 核实嵌入 AAR 与宿主打包在预定 runner 的依赖 | 记录 Linux/macOS 实际可用性；未验证前不直接沿用旧 Ubuntu 工作流假设 |

P0 任一关键项没有可实现路径，就停在技术验证阶段，记录问题、最小复现和修复方案；保留现有移动端可发布状态。框架有短板时优先经官方宿主扩展补齐；必须 fork 才能完成时，明确补丁范围、负责人和固定上游版本后重新评估成本。

### 6.2 开发执行顺序

1. 先固定 API/事件/旧数据的脱敏样本及旧客户端真机基线，建立可回填的功能编号表。
2. 从“配对 → 首屏列表 → 单项详情 → 原文件下载”贯通最小链路。
3. 完成筛选、集合、手势和同步，再接入变更操作，减少无效刷新与旧响应串库。
4. 将原生分享队列、旧数据兼容读取在 P1 就建立；P5 完成完整界面和上传闭环，避免最后才发现数据无法迁移。
5. 功能按模块提交，每步保持 Android 可构建；框架补丁、服务端补丁、客户端功能分别提交。
6. 每阶段记录实际构建命令、已测机型/系统、失败项和工作量，更新阶段进度，不能将“有实现”直接标为“已验收”。

## 7. 测试与替换验收

### 7.1 自动化与人工分工

| 层级 | 验证内容 | 执行方式 |
|---|---|---|
| Go 单元/契约测试 | 查询转义、兼容降级、DTO、错误分类、请求代次、SHA-256、持久化、迁移重试、事件去重 | `httptest`、脱敏夹具；新模块 `go test ./...`、`go vet ./...` |
| NSGo 页面测试 | 配对错误、集合切换、搜索重置、空态、动作结果、危险操作确认 | 锁定版本支持的 `nsgotest`；在 P0 确认可运行命令 |
| Android 宿主测试 | Intent 解析、URI 权限、文件桥、分享 ack、Activity 重建/销毁 | Android instrumentation 与可控测试 Provider |
| 桌面联调 | 上传、标签、目录、删除/恢复/清空、切库、三种 WS 事件及断线补刷新 | 复用现有服务端与移动 API 测试；新增后端变更时运行相应 `./core` 测试 |
| 真机验收 | 相机、剪贴板粘贴、第三方分享、MediaStore、Wi-Fi/VPN、前后台、大文件、升级迁移 | 原有分享接收清单扩展为新版验收记录 |

最终 APK/AAB 需要通过宿主 Gradle 检查、NSGo AAR 嵌入构建及签名检查；具体任务名和命令在新工程创建后固定。本轮不把尚不存在的脚本写成已可执行的项目命令。

### 7.2 关键场景

- 连接：错误配对码、电脑离线、候选 IP 部分不可达、授权撤销、深链启动、摄像头权限拒绝后重试。
- 浏览：10,000 条混合素材、2～5 列、月份边界、长按上滑/多选、滚动中刷新、连续换筛选、详情停留时库切换。
- 操作：单项/批量加标签与目录的部分失败、删除后列表与统计一致、重复删除、恢复原目录、清空后的永久删除反馈。
- 媒体：图片缩放与翻页、GIF 小/大阈值、视频 seek/后台暂停/不支持格式；大文件导出不整文件驻留内存。
- 分享：单文件、多文件、文本、文件+文本、冷启动、热启动、离线暂存、上传部分成功、重复事件、杀进程后恢复。
- 迁移：旧 token 可读/不可读、不同根目录索引与标记、未消费 pending、损坏条目、同名库、重复执行迁移。
- 兼容：当前桌面端与缺少新接口的旧端；未支持筛选明确提示；身份失效不降级为正常空列表。

### 7.3 性能与交付门槛

P0 在同一台 Android 真机上测旧 Flutter 与新 NSGo：冷启动到首个可操作页面、首屏缩略图、滚动 p50/p95、UI/Go 进程合计内存、视频 seek、100 MB 文件传输峰值、安装包大小。固定桌面版本、测试库、网络、系统和测量方法。

P0 报告填入实测值后确定预算；初始目标是新版本滚动 p95、可操作首屏耗时与总内存不高于旧版 120%，不得出现 OOM、ANR、崩溃或持续内存增长。包体先记录实测再定预算，不用官网 benchmark 推算本项目。

发布前需同时满足：

1. 功能清单全部编号有实现位置、验证方式与结果；缺口不能仅标记 TODO 后视为替换完成。
2. 至少两台 Android 真机验证，包含 arm64 主力机与一台资源较紧张设备；覆盖新版支持范围的最低系统与当前主要系统版本。最低系统版本和 ABI 支持在 P0 固定，取消旧 ABI 时需写明用户影响。
3. 旧版覆盖升级成功；未上传文件、文本、pending 和来源标记不丢失；迁移失败可重试。
4. 连续浏览/媒体/分享混合操作至少 30 分钟无崩溃、ANR、泄漏趋势；性能达到约定预算。
5. CI 能从干净环境复现产物；签名、versionCode、包名、文件命名与 Release 附件明确；应急构建方案验证完成。
6. 验证 Release 包不包含 Flutter engine、Dart 业务和 Flutter 插件依赖；开发文档不再要求 Flutter SDK。
